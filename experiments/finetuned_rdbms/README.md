# Fine-tuned RDBMS Runs

This folder contains the raw-monolithic-query RDBMS benchmark runner and the
orchestrator for the 116 circuits that have DuckDB, SQLite, and PostgreSQL
baseline timings in `analysis/training_data/rdbms_training_data.parquet`.

Prepare manifests and inspect local coverage:

```bash
python experiments/finetuned_rdbms/run_all_116.py --prepare-only
```

Run the discovered local subset, resuming into the same CSV:

```bash
python experiments/finetuned_rdbms/run_all_116.py \
  --engines duckdb,sqlite,postgres \
  --profile balanced \
  --n-runs 3 \
  --warmup 1 \
  --timeout-seconds 300 \
  --query-timeout-seconds 300
```

If the 116 `.qpy` files live outside the default local roots, add one or more
search roots:

```bash
python experiments/finetuned_rdbms/run_all_116.py --qpy-root /path/to/qpy/root
```

Outputs go to `analysis/finetuned_rdbms_116/` by default:

- `all_116_manifest.csv`: all selected hashes and baseline metadata.
- `all_116_hashes.txt`: one hash per line.
- `found_qpy_paths.txt`: local `.qpy` paths that will be run.
- `missing_hashes.txt`: selected hashes not found under the search roots.
- `results_<profile>.csv`: benchmark output from `run_finetuned_rdbms.py`.
- `runner_command.txt`: exact runner command generated by the orchestrator.

## MLOS tuning

Install/sync the new MLOS dependency, then tune the raw monolithic workload on
a pilot subset and optionally validate the winners on all discovered circuits:

```bash
python experiments/finetuned_rdbms/mlos_tune_rdbms.py \
  --qpy-root /path/to/qpy/root \
  --engines duckdb,sqlite,postgres \
  --pilot-size 12 \
  --trials 20 \
  --n-runs 1 \
  --warmup 1 \
  --validate
```

The tuner writes:

- `mlos_trials.csv`: every seed/MLOS trial row, including tuning JSON, params,
  phase, trial id, and score.
- `mlos_best_configs.json`: best tuning per engine.
- `results_mlos.csv`: validation rows when `--validate` or `--validate-only`
  is used.

The existing runner can also execute an explicit tuning without MLOS:

```bash
python experiments/finetuned_rdbms/run_finetuned_rdbms.py \
  --qpy-list analysis/finetuned_rdbms_116/found_qpy_paths.txt \
  --engines duckdb \
  --tuning-label manual_duckdb \
  --tuning-json '{"threads":4,"memory_limit":"4096MB","temp_directory":"/tmp/duckdb","preserve_insertion_order":false,"max_temp_directory_size":"256GB"}'
```

## Usage

Recorded end-to-end invocations from the published runs. All paths are relative
to the InferQ checkout root.

### 162 all-methods circuits: download, tune, run

Materialise the hash list, fetch the `.qpy` files, then tune and run against
them:

```bash
mkdir -p analysis/finetuned_rdbms_162/qpy
uv run python -c 'import pandas as pd, pathlib; out=pathlib.Path("analysis/finetuned_rdbms_162"); out.mkdir(parents=True, exist_ok=True); df=pd.read_parquet("analysis/training_data/rdbms_all_methods_training_data.parquet", columns=["RowKey"]); df["RowKey"].astype(str).to_csv(out/"all_162_hashes.txt", index=False, header=False)'
set -a; source .env; set +a
xargs uv run python inferq.transfer.download_by_hash --output-dir analysis/finetuned_rdbms_162/qpy < analysis/finetuned_rdbms_162/all_162_hashes.txt
find analysis/finetuned_rdbms_162/qpy -name "*.qpy" | sort > analysis/finetuned_rdbms_162/found_qpy_paths.txt
```

Tune each engine on a 12-circuit pilot and validate the winners:

```bash
uv run python experiments/finetuned_rdbms/mlos_tune_rdbms.py \
  --parquet analysis/training_data/rdbms_all_methods_training_data.parquet \
  --qpy-root analysis/finetuned_rdbms_162/qpy \
  --out-dir analysis/finetuned_rdbms_162 \
  --engines duckdb,sqlite,postgres \
  --pilot-size 12 --trials 20 --optimizer flaml \
  --n-runs 1 --validation-runs 3 --warmup 1 \
  --timeout-seconds 300 --query-timeout-seconds 300 \
  --tmp-root analysis/finetuned_rdbms_162/tmp_mlos_box \
  --trials-csv analysis/finetuned_rdbms_162/mlos_trials_box.csv \
  --best-configs analysis/finetuned_rdbms_162/mlos_best_configs_box.json \
  --validation-csv analysis/finetuned_rdbms_162/results_mlos_box_validation.csv \
  --validate
```

Reduce `mlos_best_configs_box.json` to the per-engine tuning the runner expects,
then run the tuned benchmark:

```bash
uv run python -c 'import json; p="analysis/finetuned_rdbms_162/mlos_best_configs_box.json"; d=json.load(open(p)); json.dump({e:v["tuning"] for e,v in d["engines"].items()}, open("analysis/finetuned_rdbms_162/mlos_runner_tuning_box.json","w"), indent=2)'
uv run python experiments/finetuned_rdbms/run_finetuned_rdbms.py \
  --qpy-list analysis/finetuned_rdbms_162/found_qpy_paths.txt \
  --out-csv analysis/finetuned_rdbms_162/results_box_tuned_162.csv \
  --engines duckdb,sqlite,postgres \
  --tuning-json analysis/finetuned_rdbms_162/mlos_runner_tuning_box.json \
  --tuning-label mlos_box \
  --n-runs 3 --warmup 1 \
  --timeout-seconds 300 --query-timeout-seconds 300 \
  --tmp-root analysis/finetuned_rdbms_162/tmp_runner_box \
  --resume
```

### Full 7,705-circuit two-profile sweep

Each circuit gets its own budget from the fastest baseline engine, floored at
100 ms, with only the contraction timed:

```bash
uv run python experiments/finetuned_rdbms/run_full_7705_two_profile.py \
  --parquet analysis/training_data/rdbms_training_data.parquet \
  --out-dir analysis/finetuned_rdbms_7705_baseline_min_floor_100ms_contraction_single \
  --out-csv analysis/finetuned_rdbms_7705_baseline_min_floor_100ms_contraction_single/results_two_profile.csv \
  --engines sqlite,duckdb,postgres \
  --timeout-policy baseline_min --timeout-floor-seconds 0.1 \
  --timing-scope contraction --query-timeout-seconds 30 \
  --n-runs 2 --warmup 0
```

The same sweep splits across four machines with `--num-shards 4` and a distinct
`--shard-index`, `--out-csv` and `--tmp-root` per shard:

```bash
SHARD=0
uv run python experiments/finetuned_rdbms/run_full_7705_two_profile.py \
  --parquet analysis/training_data/rdbms_training_data.parquet \
  --out-dir analysis/finetuned_rdbms_7705_baseline_min_floor_100ms_contraction_sharded \
  --out-csv analysis/finetuned_rdbms_7705_baseline_min_floor_100ms_contraction_sharded/results_shard_${SHARD}.csv \
  --tmp-root analysis/finetuned_rdbms_7705_baseline_min_floor_100ms_contraction_sharded/tmp_shard_${SHARD} \
  --engines sqlite,duckdb,postgres \
  --timeout-policy baseline_min --timeout-floor-seconds 0.1 \
  --timing-scope contraction --query-timeout-seconds 30 \
  --n-runs 2 --warmup 0 \
  --num-shards 4 --shard-index ${SHARD}
```

Concatenate the shard CSVs into the single result the analysis expects:

```bash
uv run python -c 'import pandas as pd, pathlib; out=pathlib.Path("analysis/finetuned_rdbms_7705_baseline_min_floor_100ms_contraction_sharded/results_two_profile.csv"); files=sorted(out.parent.glob("results_shard_*.csv")); dfs=[pd.read_csv(f) for f in files if f.exists() and f.stat().st_size]; out.parent.mkdir(parents=True, exist_ok=True); pd.concat(dfs, ignore_index=True).to_csv(out, index=False); print(f"merged {len(files)} shards -> {out}")'
```
